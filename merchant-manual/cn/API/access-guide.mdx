## 对接模式说明

### 授信模式（CREDIT_EXTENSION）

持卡人真实的资产，包括资产的充提，在商户侧系统完成闭环，所有持卡人资金由商户自己管理。

商户进行额度划转完成授信，需要充值备付金。持卡人消费时，从备付金完成资金扣除。

**适用场景：**
- 商户自行管理持卡人资金
- 需要完整的账户体系和划转功能
- 对实时性要求相对较低

### 授权模式（AUTHORIZATION）

持卡人真实的资产，包括资产的充提，在商户侧系统完成闭环，所有持卡人资金由商户自己管理。

持卡人发生消费时，KeySecure 会向商户发送授权确认，需要在**800毫秒之内**完成授权确认，否则交易失败。

**适用场景：**
- 需要实时授权确认的交易流程
- 对响应性能要求高
- 支持多种卡 BIN 组合

**重要提示：**对接口响应要求很高，需要确保系统能在 800 毫秒内完成授权应答。

### 模式选择建议

| 维度 | 授信模式 | 授权模式 |
| --- | --- | --- |
| 资金管理 | 商户管理 | 商户管理 |
| 交易确认 | 资金流水同步 | 实时授权（≤800毫秒） |
| 系统复杂度 | 中等（需要账户体系） | 高（需要实时响应） |
| 套餐管理 | 平台提供 | 商户自己维护 |

## 对接前准备

完成以下准备工作，确保顺利接入 API：

| 事项 | 说明 | 负责方 |
| --- | --- | --- |
| **选择对接模式** | 确认采用授信模式还是授权模式 | 商户 |
| **申请商户账号** | 联系商务获取测试账号和对应的 `Api-Key` 和 `apiSecret` | 商务团队 |
| **IP 白名单配置** | 提供服务器出口 IP，在后台配置到 Api-Key 对应白名单 | 商户后台 |
| **回调地址配置** | 配置接收交易通知的 URL（用于卡变动、消费订单、授权通知等） | 商户后台 |
| **集成 SumSub KYC** | 前端集成 KYC 认证组件，用户通过 Sumsub 完成 KYC 认证 | 商户前端 |
| **密钥管理** | 安全保管 `apiSecret`，用于加解密敏感信息（CVV/PIN）和验签 | 商户后端 |
| **测试对接** | 在沙盒环境完成全流程测试（用户认证→开卡→消费等） | 商户 |
